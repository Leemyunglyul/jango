# 잔고와 흐름

개인 가계부 + 자산·투자 트래커. 의존성 없는 단일 HTML 앱 + PWA.

**탭 4개** — 기록 / 내역 / 통계 / 자산 (자산 안에서 `자산 | 투자` 전환)
설정은 모바일에서 상단 아이콘, 데스크톱에서 사이드바 맨 아래.

- **모바일**: 한 줄로 흐르는 세로 레이아웃 + 숫자패드.
  하단 탭은 아이콘+글자로 58px 높이, 안전영역(`env(safe-area-inset-bottom)`) 반영
- **데스크톱(≥1080px)**: 좌측 사이드바 + 2단 구성. 숫자패드가 사라지고 **키보드로 입력**한다
  (`0`–`9` 금액 · `⌫` 지우기 · `Enter` 기록 · `M` 메모 · `T` 지출→수입→투자 · `[` `]` 달 이동)
- **테마**: 상단 아이콘으로 시스템 → 밝게 → 어둡게 순환 (`localStorage["jango.theme"]`)
- **화면**: 아이보리·딥그린 색상, 데스크톱 사이드바와 입력/잔액 요약 2단 구성.
  모바일은 상단 날짜 이동과 하단 탭, 큰 금액 입력, 계좌·종목 카드로 구성한다.

```
index.html              앱 전체 (HTML/CSS/JS 한 파일)
manifest.json           PWA 매니페스트 (홈 화면 추가용)
sw.js                   서비스 워커 (오프라인 캐시 — 앱 파일만, 데이터는 안 건드림)
icon-*.png              아이콘
apps-script/코드.gs     구글 시트 백엔드 (선택)
README-시트연결.md      ↑ 설치 안내 — 동기화를 쓰려면 여기부터
README-배포.md          GitHub에 올리고 주소 만드는 법
build.py                아티팩트용 소스 → 정적 index.html 빌드 스크립트
.nojekyll               GitHub Pages가 파일을 그대로 서빙하게
.gitignore              가계부 백업 파일이 실수로 커밋되는 걸 막음
```

외부 의존성은 두 개뿐이고 둘 다 CDN에서 로드한다.
- Google Fonts (Hahmlet, IBM Plex Sans KR, IBM Plex Mono)
- SheetJS 0.18.5 — 엑셀 내보내기에만 사용

## 3. 데이터가 어디에 저장되나

저장 계층이 세 갈래로 자동 분기한다. 위에서부터 먼저 잡히는 걸 쓴다.

| 조건 | 저장소 | 기기 간 동기화 |
|---|---|---|
| 설정에서 구글 시트를 연결함 | **내 드라이브 스프레드시트** | **된다** |
| Claude 아티팩트로 열림 | `claude.use("db")` | 된다 |
| 그 외 (그냥 웹) | `localStorage` | 안 된다 |

**권장: 구글 시트 연결.** 설치는 [README-시트연결.md](./README-시트연결.md) 참고.
데이터가 내 드라이브에 남으니 이 앱을 지워도, 호스팅을 옮겨도 기록은 그대로다.
시트를 열어서 피벗을 돌리거나 직접 고쳐도 되고, 앱에서 다시 내려받으면 반영된다.

연결하지 않으면 `localStorage`라 그 브라우저에만 남는다. 폰에서 기록한 게
PC에 안 보이고, 사이트 데이터를 지우면 날아간다. 백업은 설정 → 백업 파일(JSON).

### 동기화가 도는 방식

- 거래·자산·종목·설정·월별 투자기록을 저장하면 → `localStorage` 즉시 →
  **마지막 변경 약 1초 뒤** 시트에 자동 업로드한다. 연속 변경은 묶어서 보낸다.
- 업로드 중 추가한 변경은 앞선 요청이 끝나면 이어 올린다.
- 앱을 열면 → `localStorage`로 먼저 그리고 → 시트를 읽어서 `rev`(수정 횟수)를 비교
  - 미전송 변경이 있으면 → 로컬 변경을 보존하고 해당 항목을 시트에 올림
  - 미전송 변경이 없고 시트가 더 최신이거나 같으면 → 시트 내용을 채택
  - 이전 버전의 앱에 더 최신 내용이 남아 있으면 → 앱 내용을 시트로 올림
- 실패한 요청은 3초부터 최대 30초 간격으로 자동 재시도한다. 오프라인이면 기다렸다가
  인터넷 재연결 또는 앱 복귀 시 다시 시도한다.
- 미전송 목록은 데이터와 함께 기기에 저장하므로 새로고침·앱 재시작 후에도 이어 올린다.
  앱이 완전히 종료된 동안은 전송하지 못하며, 다시 열었을 때 동기화한다.
- 상단 칩에서 **업로드 대기 / 동기화 중 / 시트 동기화 시각 / 실패·재시도 대기**를 확인한다.
  설정의 **지금 시트로 올리기**는 즉시 전송하는 보조 기능이다.

한 사람이 폰/PC를 번갈아 쓰는 건 이걸로 충분하다. 두 기기를 **동시에** 열어놓고
양쪽에서 기록하면 나중에 저장한 쪽이 이긴다.

### 다른 백엔드로 바꾸려면

건드릴 함수는 넷뿐이다.

```js
async function flush()                 // 저장 디스패처 (여기서 백엔드 결정)
async function pushSheet(all)          // 변경분 올리기

function adoptRemote(data, rev)        // 원격 데이터를 앱 상태로 채택
```

## 3.5 버전 이관 (`migrate()`)

시드 데이터(`SEED_ASSETS` / `SEED_SNAPS`)는 **저장소가 비어 있을 때만** 적용된다.
이미 예전 구조가 저장돼 있으면 그쪽이 이긴다 — 그래서 `S.v`(DATA_VERSION) 기준 이관 함수를 둔다.

`v < 2`이고 새 투자 그룹(`isa`/`overseas`/`housing`)이 하나도 없으면:

- 자산을 새 구조로 교체하되 **사용자가 값을 넣은 `cash` / `real` / `insure` / `pension` 계좌는
  금액·대출을 살려서 옮긴다**
- 예전 "투자 계좌" 한 줄(사실은 누적원금)은 버리고 원본 시트 값으로 교체
- **거래 내역은 절대 건드리지 않는다**

`migrate()`는 부팅 시, 그리고 원격(DB/시트)에서 데이터를 받아온 직후에도 호출된다.
값이 바뀌면 `persist()`가 원격까지 밀어 올린다.

`v < 5`의 기존 스냅샷은 삭제하지 않고 별도 **월별 투자기록** 시트로 승계한다. 이후에는
계좌에 당월 납입액을 반복 저장하지 않고, 투자 탭에서 월마다 납입·인출·월말 평가액·
누적 원금·메모를 한 건으로 관리한다. 저장 시 보유 종목·수량·가격도 함께 고정된다.

## 4. 원본 엑셀 규칙 (이관 시 주의)

**① 지출 합계 = 총지출 − 적립·할인·이자**
`적립·할인·이자` 카테고리에 `deduct:true` 플래그가 붙어 있고 `summarize()`가 `net = gross - deduct`로 계산한다.
이걸 빼면 8월 지출이 1,190,659(시트값 1,185,697)로 어긋난다.

**② 원본 가계부 시트의 "투자 6,067,310"은 평가액이 아니라 누적 납입원금이다.**
실제 평가액은 종목 합계 6,004,919. 그래서 8월 기준 평가손익은 −62,391 (−1.03%).
`투자 월별 평가` 시트의 컬럼을 그대로 스냅샷 스키마로 옮겼다.

**③ 계좌별 누적 납입원금이 비어 있으면 마지막 스냅샷의 누적원금을 이어 쓴다.**
(`investTotals()`의 `fromSnap`) 원본에 계좌별 원금 분리가 없어서 총액만 있기 때문.
계좌마다 원금을 넣으면 그 값이 우선한다. **당월 납입액은 이어 쓰지 않는다** —
지난달 값이 이번 달로 새면 안 되니까.

## 4.5 투자 이체 — 월급을 투자로 옮길 때

기록 탭의 종류는 **지출 / 수입 / 투자** 세 가지다. 월급은 `수입`으로 한 번만 적고,
그중 투자 계좌로 옮긴 돈은 `투자`로 적는다. 투자로 보낸 돈을 다시 `수입`으로 적으면
들어온 돈이 두 번 잡히므로, 투자 종류(`kind:"inv"`, 거래 `k:"inv"`)를 따로 둔다.

- 투자 기록은 **수입에도 지출에도 더하지 않는다** (`summarize()`의 `invest`)
- `이번 달 남은 돈 = 수입 − 지출 − 투자`, 통계의 `저축 여력 = 수입 − 지출`(투자 포함)
- 그 달 투자 기록 합계가 **월별 투자 기록의 당월 납입액** 기본값이 된다 (`ledgerInvest()`)
- 이미 저장한 달의 납입액이 가계부 합계와 같았다면, 이후 가계부에 투자를 더 적거나
  지울 때 납입액·원금이 같이 움직인다 (`followLedgerInvest()`). 납입액을 직접 다른 값으로
  넣어 둔 달은 건드리지 않고, 기록 시트에 `가계부 투자 합계로 맞추기` 버튼만 보여 준다
  — 직접 넣은 납입액 위에 가계부 투자가 또 더해지지 않게 하기 위해서다
- 거래 종류는 분류가 정한다. 기록 수정 시트에서 분류를 투자 분류로 바꾸면 그 기록이
  투자가 되고, 설정 → 분류에서 분류 종류를 `투자`로 바꾸면 그 분류의 기존 기록도 함께 바뀐다

**기존 데이터 이관** (`normalizeLedgerKinds()`, 부팅·시트 다운로드 직후 실행) —
투자 분류가 하나도 없으면 이름에 `투자`가 들어간 수입 분류(`수익·배당·이자·환급` 제외)를
투자 분류로 바꾸고, 그래도 없으면 기본 `투자 납입` 분류를 만든다. 투자 분류가 생긴 뒤에는
이름으로 바꾸지 않는다. `기타 수입` 등 다른 분류로 적어 둔 예전 투자금은 기록 수정에서
분류를 투자로 바꿔 주면 된다.

Apps Script를 다시 배포하지 않아도 동작한다. 예전 스크립트는 `거래` 탭 구분 칸에 투자를
`지출`로 적지만, 앱이 분류 종류를 보고 다시 투자로 되돌린다. 다시 배포하면 구분 칸에 `투자`로 적힌다.

## 5. CSV 가져오기

설정 → CSV 가져오기(또는 투자 탭 → 시트 붙여넣기)에서 네 형식을 인식한다.

구분자는 자동 판별한다 — **구글 시트/엑셀에서 복사하면 탭 구분**, 파일로 받으면 쉼표 구분.
머리글 행은 앞쪽 6줄 안에서 찾으므로 범위를 조금 넉넉히 잡아 복사해도 된다.
붙여넣는 즉시 어떤 형식으로 읽었는지 입력칸 아래에 표시된다.

1. **가계부 시트** — 열이 월(`8월`, `9월(~9.5)`), 행이 항목인 피벗 표
2. **거래 목록** — `날짜,구분,분류,금액,메모,일회성` 헤더가 있는 표 (구분: `지출`·`수입`·`투자`)
3. **종목별 포트폴리오** — `계좌구분 / 투자 종목명 / 시세코드 / 보유수량 / 현재가` 열 → 종목·비중으로.
   계좌구분 텍스트를 그룹으로 매핑(ISA·해외직투·국내·연금·청약)하고,
   오른쪽에 붙은 요약표나 합계 행은 계좌/종목 칸이 비어 있어서 자동으로 걸러진다
4. **투자 월별 평가** — `당월 투자 납입액 / 누적납입원금 / ISA 평가액 …` 열 → 월별 투자 기록으로

### 월별 투자 기록

투자 탭의 **월별 투자 기록**에서 달마다 한 줄을 저장한다. 같은 달을 다시 저장하면
중복 행을 만드는 대신 그 달 기록을 수정한다.

- 입력: 당월 납입액, 당월 인출액, 월말 투자 평가액, 메모
- 누적 원금은 이전 기록의 원금 + 당월 납입 − 당월 인출로 자동 계산한다.
  첫 기록에 이전 투자분이 있다면 `원금 직접 보정`으로 누적 원금을 한 번 입력한다.
  이미 저장된 달은 기존 원금에 납입·인출 변경분만 반영하며, 직접 보정도 가능하다.
  과거 기록 수정은 해당 월만 반영한다. 이후에 이미 저장된 월의 원금은 유지한다.
- 자동 보관: 계좌별 평가액과 종목별 수량·평단·현재가
- 자동 계산: 순입금, 시장손익, 월수익률, 누적 평가손익
- 과거 달은 표의 `수정` 버튼으로 고치거나 삭제할 수 있다

시장손익은 `이번 달 평가액 - 지난달 평가액 - 납입 + 인출`로 계산한다.
월수익률은 월중 입출금이 중간에 있었다고 보는 간이 수익률이다.

Google Sheets의 `월별 투자기록` 탭은 다른 데이터 저장과 분리되어 있다. 저장 시
탭 전체를 비우지 않고 해당 월 행만 추가·수정하므로, 앱이나 Apps Script를 다시
배포해도 기존 월 기록이 삭제되지 않는다. 예전 `스냅샷` 탭은 최초 이관 원본으로만
읽고 이후에는 수정하지 않는다.

백엔드 v6부터 앱 시작 시 변경 번호가 같아도 시트를 다시 읽는다. 또한 기존
`투자 월별 평가` 탭과 `스냅샷` 탭을 매번 확인해 `월별 투자기록`에 빠진 달만
자동 이관한다. 따라서 9월 기록이 먼저 있어도 원본의 8월 기록을 함께 표시한다.

## 6. 자산 증가율

자산 화면의 **증가율 기준 설정**에서 기준일·총순자산·부동산 제외 순자산을 저장하면
현재 자산과의 증가액 및 증가율을 확인할 수 있다. 기준은 설정 데이터로 시트에도 동기화된다.
부동산 제외 금액은 부동산의 순가치(현재가치 − 해당 계좌 담보대출)를 함께 제외한다.
기준 금액이 0 이하이면 증가액만 표시한다. 저축도 순자산 증가에 포함된다.
별도의 금융투자 월수익률은 가장 최근 연속된 두 달의 저장 기록으로 계산하며,
납입·인출을 월중 중간 시점으로 가정한 간이 수익률이다. 월별 투자 기록이 부족하면 표시하지 않는다.

## 6.5 달 이동과 추이

상단의 달 이동(`‹ ›`)이 **모든 탭**에 적용된다. 자산·투자 탭도 고른 달의 상태를 보여 준다.

- **이번 달** — 지금 계좌·종목 값(실시간). 편집은 이번 달에서만 한다.
- **지난달** — 그 달 기록으로 그린 읽기 전용 화면. 위에 `이번 달로` 버튼이 붙는다.
  1. 그 달 **월별 투자 기록**을 저장했다면 그 값(사용자가 확정한 월말 값, 보유 종목 포함)
  2. 없으면 **자동 기록** — 앱이 이번 달 자산 합계를 `settings.history[YYYY-MM]`에 남기고
     (`captureHistory()`, 부팅·시트 다운로드·자산 저장 시) 달이 바뀌면 마지막 값이 그대로 굳는다.
     구분별 합계만 남고 종목 목록은 없다. 설정과 같이 시트 `설정` 탭에 저장되므로 Apps Script를
     다시 배포할 필요가 없다.
  3. 둘 다 없으면 "기록 없음"
- **다가올 달** — "아직 오지 않은 달"

각 탭에는 **추이 막대**가 있다. 막대를 누르면 그 달로 이동하고, 선택한 달과
지난달의 차이(금액·%)를 보여 준다. 지출은 줄면 초록, 나머지는 늘면 초록이다.

기간은 **6개월 / 1년 / 3년 / 연도별** 중에서 고른다. 고른 기간은 모든 탭에 같이 적용되고
그 기기에 기억된다(`localStorage["jango.trend"]`).

- 1년·3년 — 달마다 막대 하나. 3년은 막대가 촘촘해서 1월(`25년`)과 분기 첫 달만 이름을 붙인다.
- 연도별 — 기록이 처음 시작된 해부터 올해까지(최대 30년) 해마다 막대 하나.
  - 지출·남은 돈·저축 여력처럼 **달마다 생기는 값은 그해 합계**, 자산·평가액처럼
    **잔액인 값은 그해 마지막 기록**으로 묶는다 (`trendStrip`의 `kind: "flow" | "stock"`).
  - 올해 합계는 진행 중이라 **작년 같은 기간**(1월~이번 달)과, 잔액은 **작년 말**과 비교한다.
  - 해를 누르면 그해 12월(올해는 이번 달)로 이동한다.
- 기록이 시작된 첫해는 일부 달만 있어서 연 합계가 작게 나온다.

| 탭 | 추이 |
|---|---|
| 기록 | 남은 돈 (수입 − 지출 − 투자) |
| 내역 | 지출 |
| 통계 | 저축 여력 (수입 − 지출) |
| 자산 | 총순자산 + 구분별 금액 옆 지난달 대비 증감 |
| 투자 | 투자 평가액 + 그 달 납입·시장손익, 월별 기록 표에서 선택한 달 강조 |

## 7. 무료 현재가·환율

구글 시트를 연결하면 자산 화면의 **시세 새로고침**으로 Apps Script가
미국 종목·환율은 `GOOGLEFINANCE`, 국내 종목은 네이버 증권 공개 시세를 읽는다.
별도 유료 API나 API 키는 필요 없다.

- 미국 종목: `NASDAQ:QQQ`, `NYSEARCA:VOO`처럼 입력한다. 달러 현재가와
  `USD/KRW` 환율을 함께 받아 원화 현재가로 계산한다.
- 국내 종목: `379810`처럼 6자리 코드만 입력하면 `KRX:379810`으로 연결한다.
  `KRX:005930`, `KOSDAQ:247540`, `A379810`, `379810.KS` 형식도 인식한다.
- ISA의 **KODEX 미국나스닥100 → 379810**, **KODEX 미국S&P500 → 379800**을
  자동 인식한다. 띄어쓰기·대소문자·두 상품의 옛 TR 명칭을 허용하며, 이미 저장된
  보유 종목도 앱 실행 및 시트 다운로드 후 보정한다. 수량·평단·기존 가격은 유지한다.
  종목 코드는 [삼성자산운용 상품 안내](https://m.samsungfund.com/etf/insight/newsroom/view.do?seqn=76813)에서 확인할 수 있다.
- 새 종목 등록 시 **시세코드**를 같이 넣으면 등록 직후 현재가를 조회한다.
  `QQQ`, `VOO`처럼 종목명 자체가 미국 티커면 시세코드를 비워도 자동 연결한다.
- 조회 결과는 5분간 캐시하며, 조회 실패 시 기존에 입력한 현재가를 지우지 않는다.
- 자산 카드에서 연결된 코드와 조회 여부를 확인할 수 있다. 조회 실패 시 종목 편집창에
  공급자가 반환한 오류를 표시하므로 코드 미연결과 시세 서버 오류를 구분할 수 있다.

코드 인식 수정은 앱 변경만 배포하면 적용된다. 연결한 Apps Script는 기존 v6 이상이 필요하다.

검증: `node --test tests/*.test.cjs`로 자동 동기화, KODEX 코드 보정, 시세 응답 처리, 투자 이체 집계, 월별 자동 기록·추이를 확인한다.

시세는 지연될 수 있고 지원하지 않는 종목도 있다. 그런 종목은
시세코드를 비워 두고 현재가를 직접 입력하면 된다.
